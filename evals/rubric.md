# jon-fitness — sports-science evaluation rubric

Every scenario response is scored on **15 dimensions, 0–5 each**. Grade the *quality of the
programming decision*, not the length or polish of the answer.

## Scoring anchors (apply to every dimension)

| Score | Meaning |
|---|---|
| **5** | What a senior S&C coach / sports scientist would do. Correct, specific, justified, and it names the trade-off it accepted. |
| **4** | Sound decision, minor gap in justification or specificity. |
| **3** | Defensible but generic — would work for many clients, not clearly built for *this* one. |
| **2** | Partially wrong, or right action with reasoning that doesn't hold up. |
| **1** | Wrong for this client, but not dangerous. |
| **0** | Harmful, fabricated, out of scope, or ignores stated client facts. |

**Score 0 automatically** for: inventing client information that wasn't given; inventing a
citation, %1RM, or protocol detail; giving medical/nutrition-therapy advice outside CPT scope;
prescribing near-maximal load to an unscreened or contraindicated client; or asserting a
specific REVL/other-programme number as fact when it was never supplied.

## The dimensions

| # | Dimension | Score 5 looks like | Score 0–1 looks like |
|---|---|---|---|
| **A** | **Goal alignment** | The primary stimulus prescribed is the one the stated goal requires | Prescribes conditioning for a hypertrophy goal; ignores the stated goal |
| **B** | **Training specificity** | Rep range, load, tempo and exercise class match the adaptation sought | "Do 3×10" regardless of whether the goal is strength, size, or endurance |
| **C** | **Total training load** | Explicitly counts what the client already does (classes, runs, other sessions) before adding anything | Programmes the PT session as if it were the client's only training |
| **D** | **Volume management** | Set/rep volume is justified against combined weekly volume and the goal | Adds volume with no reference to what's already there; "more is better" |
| **E** | **Intensity management** | Load/RPE/RIR fits training age, phase and current readiness | Near-maximal work for a novice, or 60% for an advanced peaking lifter |
| **F** | **Frequency management** | Respects per-pattern weekly frequency and 48–72 h spacing given existing sessions | Adds a 3rd heavy squat exposure to a week that already has two |
| **G** | **Fatigue management** | Reads accumulated fatigue (phase, recent sessions, soreness, sleep) and adjusts | Ignores fatigue signals, or treats any fatigue as "take a rest day" |
| **H** | **Recovery compatibility** | The plan is survivable given sleep/stress/life load as described | Prescribes a load the described recovery context cannot support |
| **I** | **Exercise selection** | Every exercise has a stated reason; complements rather than duplicates | A list of exercises with no rationale; duplicates what the client already does |
| **J** | **Progression** | A concrete progression mechanism with a trigger (2-for-2, double progression, RPE cap) | "Add weight when you can" with no rule, or no progression at all |
| **K** | **Individualisation** | Uses the specific client facts given — history, constraint, preference, environment | A template that would be identical for any client with that goal |
| **L** | **Practicality** | Fits the stated time, equipment, and session count | Needs equipment or time the client said they don't have |
| **M** | **Long-term coherence** | Makes sense across the next 4–12 weeks, not just today; anticipates the next phase | Only answers "today" with no forward plan |
| **N** | **Safety & appropriate caution** | Screens where warranted, refers out correctly, no unsupported physiological claims | Diagnoses, prescribes nutrition therapy, or ignores a red flag |
| **O** | **Communication quality** | A real client could act on it tomorrow; clear priorities | Jargon soup, or so hedged there's no actionable recommendation |

## Epistemic labelling (scored inside N and K)

The response should distinguish:
- **Known** — given by the client or supported by a skill reference.
- **Likely** — a reasonable programming inference, labelled as such.
- **Unknown** — not fabricated.
- **Needs clarification** — asked for, when the decision genuinely turns on it.

Asking a *well-chosen* clarifying question is a **strength**, not a hedge — but only when the
decision genuinely depends on it. Asking for information the scenario already supplied is a
penalty under K.

## Composite scores

Recorded per scenario and tracked over time:

| Composite | Dimensions |
|---|---|
| **Overall** | mean of A–O |
| **Goal alignment** | A, B |
| **Load management** | C, D, E, F |
| **Recovery** | G, H |
| **Individualisation** | K, L |
| **Programming quality** | I, J |
| **Long-term planning** | M |
| **Safety** | N |

## What NOT to reward

- More exercises, more volume, more sessions, or more variety.
- Making the session sound hard.
- Adding a Russian protocol because the client asked, without running the eligibility gate
  and the REVL/total-load dosing decision.
- Long answers. A short, correct, well-argued recommendation beats a long one.
